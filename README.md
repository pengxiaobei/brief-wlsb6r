# 每日简报

私人用途。网页：https://pengxiaobei.github.io/brief-wlsb6r/

## 文件各管什么

| 文件 | 谁改 | 说明 |
|---|---|---|
| `template.html` | **没人自动改** | 页面外壳 + 全部 CSS。排版已在真机验证过，别动 |
| `today.json` | 日更任务 | 当天全部条目。一天三轮往里加，不覆盖 |
| `watchlist.json` | 周更任务 | 观察名单状态，周更靠它做 diff |
| `weekly.json` | 周更任务 | 本周的变化日志 |
| `prompts/` | 手改 | 两个任务的提示词。改文风改这里，不用重建任务 |
| `fetch_column.py` | 手改 | 抓猫笔刀最新那篇。换公众号改文件顶上的 `FEED` 常量 |
| `column_raw.txt` | 脚本生成 | 抓来的原文，**已 gitignore**。跟踪它会让每轮都产生 diff，空转机制就废了 |
| `index.html` | `build.py` 生成 | **不要手改**，改了下次会被覆盖 |
| `archive/` | `build.py` 生成 | 每天存一份 |

日更和周更改的是不同文件，不会互相覆盖。

## 改完怎么生效

```bash
python3 build.py
```

它把 `today.json` + `watchlist.json` + `weekly.json` 灌进 `template.html`，生成 `index.html` 和当天存档。
自动任务只写 JSON、不碰 HTML，所以改不坏排版；内容里的特殊字符会被转义，注入不了。

## today.json 长这样

```json
{
  "date": "2026年8月6日 星期四",
  "stamp": "2026-08-06",
  "note": "文末那行数据时间说明",
  "runs": ["07:00", "11:30"],
  "items": [
    {"kind": "talk", "at": "11:30", "title": "一句话标题", "body": "正文 2-4 句，不放链接"},
    {"kind": "you", "at": "07:00", "title": "早上就有的", "body": "正文原样不动",
     "updates": [{"at": "11:30", "text": "这件事后来的新进展"}]}
  ],
  "sources": [{"name": "来源名", "url": "https://..."}]
}
```

- `kind` 只能是 `talk`（在聊）、`you`（影响你）、`tech`（科技）三选一
- `at` 是这条**首次进来**的轮次，页面靠它把条目按轮次分段
- `runs` 是今天跑过哪几轮。页面靠它显示「最后更新」，也靠它判断读者手机上的缓存旧没旧
- `updates` 可选，是后面几轮补的新进展 —— **原条目的 `body` 永远不改写**

## 内容规矩

- 大白话，术语就地翻译，**正文不放链接**
- 禁新闻腔：据悉、值得关注、业内人士表示、引发热议
- **增量轮宁可空转也不凑数**：没有新事、也没有实质新进展，就什么都不写
- **同一件事只能出现一次**：有后续就往 `updates` 里加，不许开新条目
- 周更只报变化，**刚冒头排最前**，在降温排最后
- 不做严肃时政舆论

## 猫笔刀那一块

页面上「猫笔刀昨晚说了什么」是每天总结他公众号最新那篇，8-12 条。

取数走 [wechat2rss](https://wechat2rss.xlab.app/) 的公开实例，**不是**直接读微信 ——
`mp.weixin.qq.com` 对非微信环境有验证墙，会返回「环境异常」；搜狗微信也查不到这个号；
`maobidao.net`、`wwyy.org`、`qnmlgb.tech` 几个志愿者镜像都已经停更，别再试了。

他晚上 22:20 前后发，feed 平均 6 小时延迟，所以早上 07:00 那轮拿到的永远是「昨晚那篇」。
超过 30 小时没更新就不放（宁可缺一块，也不把前天的当昨晚端上来）。

**这一块的选题禁区不适用** —— 他本来就是财经博主，股市涨跌照原样总结。
但文风铁律照旧：大白话、术语翻译、不放链接、他的观点要写成「他觉得……」跟事实分开。

`wechat2rss` 是免费第三方服务，随时可能挂。挂了的话 `fetch_column.py` 打印原因、
退出码仍然是 0，当天页面上少这一块，其余照常 —— **不会拖垮整个日更**。

## 怎么跑起来的

全自动，跑在 GitHub Actions 上，不依赖任何本地机器。

| 工作流 | 时间（北京） | 干什么 |
|---|---|---|
| `.github/workflows/daily.yml` | **07:00 / 11:30 / 17:00** | 写 `today.json`。首轮从零生成，后两轮只补增量 |
| `.github/workflows/notify.yml` | 08:00 | 只发飞书，推当天最重要的**一条**，把人引到网页 |
| `.github/workflows/weekly.yml` | 每周一 09:00 | `watchlist.json`、`weekly.json` |

日更每轮：跑 Claude 生成内容 → `build.py` 出页面 → 用内置 `GITHUB_TOKEN` 提交。
**空转轮什么都不改，`git diff` 为空就自动跳过提交**，这是正常结果，不是故障。

推送为什么单独拆一个工作流：生成在 07:00、提醒在 08:00，时间点不一样；
隔开一小时也够 Actions 的调度延迟（常见 5-15 分钟）兜底。

> **所有工作流都设了 `TZ: Asia/Shanghai`，别去掉。** runner 默认是 UTC，
> 而这份简报从头到尾按北京时间算 —— 07:00 那轮实际跑在 23:00 UTC，
> 不设时区的话 `date` 会拿到前一天，`stamp` 写错、检查步骤判定不新鲜、整轮内容不提交。

**想调文风或选题标准，改 `prompts/` 里那两个文件就行**，不用动工作流。

想手动补跑：仓库 Actions 页面点 "Run workflow"，或者 `gh workflow run daily.yml`。

## 两个 secret

- `CLAUDE_CODE_OAUTH_TOKEN` —— `claude setup-token` 生成，走 Max 订阅，不额外计费
- `FEISHU_WEBHOOK` —— 群机器人地址。**卡片标题必须含「简报」二字**，群里配了关键词校验

## 停更了怎么办

`notify.py` 每天早上都会检查 `today.json` 的日期是不是今天，不是就发**红色告警卡片**——
所以停更不会静默，飞书里能看到。它按北京时间算日期（写死 +8），不看运行环境的时区。

收到告警后去仓库 Actions 页面看最近一次运行挂在哪一步。最可能的原因是订阅令牌过期，
重新跑一次 `claude setup-token` 换掉那个 secret 即可。
