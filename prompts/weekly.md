# 周更：什么在冒头，什么在凉

你在维护一份观察名单。读者不一定真去做什么，就是想比身边人早点看到东西在往哪儿走。全程用中文。

## 你要改的文件

只有两个：`watchlist.json` 和 `weekly.json`。

**不要碰 `index.html`、`template.html`、`today.json`** —— 前两个改了会破坏排版，第三个归日更任务管。

## 第一步：读名单

```bash
cat watchlist.json
```

`stage` 只能是这四个值之一，代表一个东西所处的阶段：

`刚冒头` → `正在起飞` → `已经很热` → `在降温`

## 第二步：逐项复查

对每一项用 WebSearch 查最近动向，判断它现在该在哪一段。判断依据，严格按这个来：

| 看到什么 | 判定 |
|---|---|
| 只有国外在火，国内还没动静 | 刚冒头 |
| 搜索量/上架量在涨，普通人还没听说 | 刚冒头 |
| 大厂或大量同行开始进场 | 正在起飞 |
| 上了热榜、身边人开始聊 | 已经很热 |
| 安全问题、监管、「乱象」开始上媒体 | 已经很热的后半段，下一步就是降温 |
| 溢价崩掉、同行挤满、头部自己说要减速 | 在降温 |

**搜不到新消息不等于降温**，那通常只说明它这周没动静，**保持原状态不变**。只有找到明确证据才改 stage。

## 第三步：找新苗头

搜 2-3 个名单上没有的、正在冒头的东西。**优先找「刚冒头」那一档**——名单上已经一堆「正在起飞」和「已经很热」了，早期的才稀缺。

方向参考：某个东西在国外火了国内还没起来、小众玩法开始变主流、某个老品类被年轻人改造。

**找不到就不加，不要为了凑数硬塞。** 一周一个都没有是完全正常的。

## 第四步：暂时不要移出任何项目

`weekly.json` 支持 `out` 类型，但**现在不要用**。读者明确说过名单先保持现状、以后再处理退休规则。

所以这一轮只做两件事：**改 stage** 和 **加新项**。

## 第五步：写回两个文件

### `watchlist.json`

- stage 变了的：改 `stage`，`since` 改成今天，`evidence` 换成新证据
- stage 没变的：**整项不动**（`since` 记的是「什么时候变成现在这个状态的」，别刷新它）
- 新增的：追加到 `items`，`since` 填今天
- 顶上的 `updated` 改成今天

### `weekly.json`

```json
{
  "updated": "2026-08-06",
  "changes": [
    {"type": "new", "name": "视频播客", "to": "刚冒头", "why": "为什么值得注意，2-3 句"},
    {"type": "up", "name": "笔尖密逃", "from": "刚冒头", "to": "正在起飞", "why": "凭什么判断它升了"},
    {"type": "down", "name": "拼豆", "from": "已经很热", "to": "在降温", "why": "凭什么判断它降了"}
  ]
}
```

`type` 只能是 `new` / `up` / `down`。这周一项都没变就写 `"changes": []`，页面会自动显示「这周没动静」。

**两个 JSON 都必须合法，中文不要转义成 \u 编码。**

## 文风铁律

- **必须大白话。** 读者明确说过正式表述「很多其实看不懂」。
- 术语就地翻译。写「环比下降 11%」不行，要写「比上个月少了一成」。
- 不许新闻腔：据悉、值得关注、业内人士表示、引发热议。
- `why` 里**不要放链接**。
- **正在凉的和正在起来的一样重要**，别只报好消息。一个东西开始凉，对读者的价值不比它开始火低。

## 第六步：生成页面并推送

```bash
python3 build.py
git add -A
git -c user.name=weekly-brief -c user.email=bot@example.com commit -m "周更 <今天日期>"
git push origin HEAD:main
```

`build.py` 会从这两个 JSON 生成「本周」那一段，包括变化列表和名单全景板。脚本报错就把错误原样贴出来，**不要绕过它去手写 HTML**。

## 最后报告

1. 这周有几项变了，分别变成什么了
2. 新加了什么（没有就说没有）
3. 推送成功还是失败（失败贴原始错误）
