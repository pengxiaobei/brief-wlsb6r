# 日更：今天 5 条

读者是一个普通上班族，通勤路上在手机上看，只愿意花 1 分钟。全程用中文。

## 第一步：确认日期

```bash
date "+%Y年%m月%d日"
date "+%A"
date "+%Y-%m-%d"
```

## 第二步：搜集素材

用 WebSearch 搜过去 24 小时的信息，覆盖这三类，**就这三类，不要加别的**：

1. **在聊**（`talk`）—— 大家正在讨论、讨论度高的事
2. **影响你**（`you`）—— 会实际影响普通人生活的：政策、油价、天气台风、调休、物价、社保
3. **科技**（`tech`）—— AI 和新科技的重要进展

搜索词自己调整，参考：`今日 热搜 热点 新闻 <今天日期>`、`国内 政策 油价 天气 <今天日期>`、`AI 新模型 发布 <本月>`、`world news top stories <today>`。

也可以 WebFetch `https://rebang.today/home?tab=douyin` 和 `https://rebang.today/home?tab=weibo` 看实时热榜——这两个能正常读取。**tophub.today 会返回 403，别浪费时间试。**

## 第三步：挑 10 到 12 条，并且**按重要性从高到低排序**

这是最关键的一步，因为内容分两层用：

- **前 5 条会推到飞书**，读者通勤时只看这 5 条 —— 所以第 1 到 5 条必须是当天最值得知道的
- **全部 10-12 条上网页**，读者有空的时候翻

所以排序不是可选项。**第 1 条要是当天最该知道的那条，第 12 条是"有空看看也行"的那条。**
写完之后自己回头检查一遍顺序，问自己：如果读者今天只看得到前 5 条，漏掉的会不会有他真正在意的？

配比不用卡死，按当天实际素材来。大致保持三类都有，别 12 条全是科技。

挑选标准是**读者看了会不会改变判断或行动**，不是转发量。

### 这几类不要选

- **严肃时政**：中美博弈、外交表态、领导人活动、国际制裁反制、战争动态
- **社会舆论纷争**：谁举报谁、司法争议、网络骂战
- **恶性刑事案件**：拐卖、凶杀、性侵
- **纯资本市场行情**：大盘涨跌、板块轮动、基金持仓、财报数字本身、任何形式的买卖建议
- 明星八卦

判断方法：如果这条新闻**读者读完除了情绪波动之外没有任何可用信息**，就不要选。
「油价涨了 5 毛」他明天加油用得上，「某国对某国表态」他用不上。

### 关于公司上市、估值、融资——可以写，但要写对

读者说过这类他觉得有价值，前提是**落点在「这家公司做的东西」上，不是在数字上**。

✅ 可以这么写：「做机器狗的宇树要上市了，估值拉得很满」——先说它是干什么的，
再用估值当佐证说明市场多看好它。读者记住的是"人形机器人这条线走到资本市场了"。

❌ 不要这么写：「宇树科技发行价 150.8 元，市盈率 219 倍，募资 61 亿」——
这是财经快讯，读者读完只记住一堆数字，没有任何可用信息。

**一句话：产品是主角，数字是配角。** 如果一家公司做的东西本身不值得说，
那它上不上市也不值得说。

## 第四步：写

每条：一句话标题（不超过 20 字）+ 正文 2-4 句。

**文风铁律，最重要的部分：**

- **必须大白话。** 读者明确说过正式表述「很多其实看不懂」。
- 任何术语必须就地翻译。反面例子：写「形式化证明」不行，要写成「证明写成了机器能一条条核验的格式，所以不存在蒙对」。写「环比下降 11%」不行，要写成「比上个月少了一成」。
- 不许出现新闻腔：据悉、值得关注、业内人士表示、引发热议、持续发酵。
- **正文里绝对不放链接。** 读者是为了省时间才看简报的——这是他明确提的要求。

## 第五步：写 today.json

在仓库根目录写 `today.json`：

```json
{
  "date": "2026年8月6日 星期四 · 前 5 条 1 分钟，全部约 3 分钟",
  "stamp": "2026-08-06",
  "note": "内容为 8 月 6 日。",
  "items": [
    {"kind": "talk", "title": "最重要的那条", "body": "正文 2-4 句。"},
    {"kind": "you", "title": "第二重要", "body": "..."}
  ],
  "sources": [
    {"name": "来源名", "url": "https://..."}
  ]
}
```

- `kind` 只能是 `talk` / `you` / `tech`
- **`items` 的顺序就是重要性顺序**，前 5 条会被推到飞书，务必排好
- `date` 结尾那句「· 前 5 条 1 分钟，全部约 3 分钟」保留不变
- `stamp` 用 `YYYY-MM-DD`，存档文件名靠它
- `sources` 放你实际用到的来源，8-12 个

## 第六步：生成页面

```bash
python3 build.py
```

它会把 `today.json` 和 `weekly.html` 灌进 `template.html`，生成 `index.html` 和 `archive/<stamp>.html`。

**不要手改 `index.html`、`template.html`、`weekly.html`、`watchlist.json`。** 前两个改了会破坏排版，后两个归周更任务管。

脚本报错就把错误原样贴出来，不要绕过它去手写 HTML。

## 第七步：提交推送

```bash
git add -A
git -c user.name=daily-brief -c user.email=bot@example.com commit -m "日更 <stamp>"
git push origin HEAD:main
```

## 最后报告

1. 推送成功还是失败（失败贴原始错误）
2. 你选的 5 条标题，各自标了什么 kind
3. 有没有哪条你拿不准该不该选
